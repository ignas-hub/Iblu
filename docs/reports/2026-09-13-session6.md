# Session 6 — multi-account, code side

Run 2026-09-13 evening against `docs/plans/2026-09-13-sessions5-8.md` §2.

## What exists now that did not

Most of this session was already standing when it started. The three Google
Workspaces — `ignas@blanklabel.team`, `admin@deadlift.io`,
`ignacio@chocoagency.com` — were authorized earlier the same day, each with its
own Cloud project and OAuth client, and all three have been collecting mail,
Chat and calendar changes since. What was missing was the other half: Ignas
could *record* from three accounts but could only *read* from one.

**The read tools take an `account`.** Gmail, Chat and Drive/Docs reads accept
`account='blt' | 'deadlift' | 'choco'`, defaulting to `blt`, threaded down to
the `build_service(..., account=...)` call that already supported it. An unknown
alias fails with an error that lists the valid ones, from a single helper rather
than a string repeated in ten places. This is a parameter, not ten new tools —
§0 rule 9, and the cheaper half of it: new capabilities over existing data are
views of the read tool for that domain.

**The send tools take it too**, because Ignas needs to send *as* the right
identity, and they stay in the ask class. `tests/test_tool_permissions.py`
passed unchanged, which is the point of having it.

**`server_health` answers per account** — token present, credentials loadable —
reusing the existing single-account probe rather than growing a second one. One
account failing reports as that account's status and does not fail the check.

## What the repo contradicted

- **`IBLU_ACCOUNTS='blanklabel:ignas@blanklabel.team,…'`** was the brief's
  design. The repo shipped `GOOGLE_ACCOUNTS='blt,deadlift,choco'` with per-alias
  `GOOGLE_ACCOUNT_<ALIAS>_CLIENT_ID` / `_CLIENT_SECRET` / `_TOKEN_FILE`. The
  repo won; the primary alias is `blt`, not `blanklabel`. Renaming it would have
  meant re-authorizing the original account for nothing.
- **§2's acceptance D4–D5 ("run automatically on the first tick after the token
  files appear")** was already satisfied before the session began — the tokens
  appeared hours earlier and the tick summary has been showing per-account
  counts since. Nothing to arrange.
- **§9's first NEEDS-IGNAS item — paste `oauth_client.choco.json` and
  `oauth_client.deadlift.json`, then click Allow twice — is already done.** It
  is struck from the list rather than carried forward.
