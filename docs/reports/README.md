# Session reports

One file per build session, `2026-09-<dd>-session<N>.md`. Each is written at the
end of its session, committed with the work it describes, and summarised in one
message to the Secretary Chat space.

The format is fixed, and the order is the point — it is the same order every
IBLU output uses, because it is the practice the whole system is built around:

1. **What exists now that did not** — dated, with evidence. Gains first, always.
2. **What the repo contradicted** — where the plan and the code disagreed, and
   which one won. The repo wins by default; every exception is recorded here.
3. **What needs Ignas** — collected, never blocking. A session does not stop to
   wait for him.

No "remaining", no percentages against a plan, no distance from a target. A
report that grades the session would be measuring the Gap, which is the exact
habit IBLU exists to replace.
